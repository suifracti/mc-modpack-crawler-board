# 下一轮：跨平台本地浏览器服务与采集更新

2026-09-20。用户已选择“看板＋采集更新：能浏览，也能在软件里更新数据”。Codex 负责方案与审核，用户转发，lunamax 实施。

## 交付目标

交付可在 Windows、macOS 和 Linux 启动的本地浏览器服务：浏览整合包、选择平台更新数据、看到真实进度与结果。服务监听 localhost 并可自动打开默认浏览器；当前不再交付 Electron EXE，也不做生产 cutover。

## 基线与工作方式

从包含本文的 `codex/repository-cleanup` 整理提交创建一个 `codex/desktop-dashboard` 分支，继续使用这一分支返修；一个 PR 完成本轮。先记录实际 base SHA，检查工作树，复用现有前端和 Python 实现。

不要 cherry-pick A/B 候选；不要修改生产 `converted_output/` 或运行仓库 cutover；不要开启另一轮全人口归组审计或 Truth Matrix 定稿。这些历史限制已在 [PROJECT_STATUS.md](PROJECT_STATUS.md) 记录。

## 产品与 UI

主线是“找包 → 判断适配 → 版本/Loader/服务端证据 → 模组/评论/来源 → 原站”。先让用户知道能做什么、下一步做什么。

- 首页搜索与结果优先，使用已有的有效筛选，避免大块无意义 KPI 占据首屏。
- 详情渐进展开，摘要之后能看到来源证据；数据缺失显示未知，不能编造兼容性或硬件适配结论。
- 保留原始来源与视频查看入口。可以压缩像素，不能压缩事实。
- 延续现有工坊/岩板色系、明暗主题和平台辨识度，统一间距、字号与操作层级；本轮只改完成桌面流程所需的导航与界面，不全盘重写所有平台详情。
- 更新面板：选择平台 → 开始 → 当前阶段/已处理数量 → 成功、失败或已取消。没有总量时不显示假百分比。日志可展开，不把终端输出当作全部交互。

## 实现要求

采用 Node.js 本地 HTTP 服务，复用 `apps/web` 的预构建资源；Python 作为现有采集/数据后端。浏览器端通过同源 HTTP API 与 SSE 使用窄接口。若发现明确技术障碍，先报告具体障碍和最小替代方案，不重迁整个项目。

1. 将应用资源与可写数据分开。用户数据放系统用户数据目录；支持中文与空格路径；打包文件夹可以只读。缺数据时显示可操作的空状态，允许选择已有本地数据，不能假装 clone 自带完整数据。
2. 保持六个平台可选择，调用现有实际参数；统一入口必须显式传平台。后台只有一个更新任务，重复点击不启动并发采集。需要登录/访问受限时显示真实原因，不能默默跳过再显示全成功。
3. 更新在隔离目录完成采集、canonical/导出和完整性检查，成功后才替换应用当前数据快照，保留上一份可用数据。失败、取消、应用退出后重启仍能浏览旧数据；未选择的平台已有数据不能丢失。
4. 不调用统一爬虫的 `--auto-convert` 覆盖现代看板。拆出复用的数据步骤，避免在终端用户机器运行 npm 构建。关闭/取消时清理本应用的任务进程树，不影响其他 Python、Node 或浏览器进程。
5. 浏览器页面不获得 Node 或文件系统权限，通过固定同源 API 执行选择平台、启动、取消和状态订阅。服务校验参数，不暴露任意命令执行；原站链接只允许合法 http/https 并在浏览器新标签页打开。
6. 日志和打包结果不包含 Cookie、token、浏览器 profile、`.git`、个人数据库或整份审计目录。采集登录态留在用户数据目录，不回显凭据。

## 一次收口的验证

保留现有 typecheck/Vitest；新增测试聚焦任务调度、参数边界、取消、失败保留旧数据与成功切换，避免测试只复述实现。

在本地浏览器服务上验证：启动 → 浏览器搜索/筛选/详情 → 一个平台最小范围真实采集 → 数据刷新 → 服务重启仍可查看；再验证取消和失败保留原数据。六平台完成调度与参数路径检查；若某平台无法限量采集，不为验收强行全网重抓，明确记录真实联网验证范围。至少给出一条真实成功更新的证据；网络阻塞就如实说明，不以 mock 冒充完成。

交付：源码提交与 PR、可运行包的本地路径及 SHA256、简短启动说明、验证结果、尚存限制。交回 Codex 后停止，不自行合并或发布 Release。
